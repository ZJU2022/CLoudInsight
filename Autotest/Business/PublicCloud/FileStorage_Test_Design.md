# 文件存储自动化测试设计思路

## 概述

本文档详细描述了文件存储产品线（UFS - Unified File Storage）的自动化测试设计思路，包括业务本质理解、功能点梳理、自动化交付产物设计、测试策略制定以及具体实施方案。文件存储是云服务中的核心存储服务，为云主机提供高性能、可扩展的共享文件存储能力。

## 第一步：业务本质与实例类型梳理

### 业务本质理解

#### 1. 什么是文件存储（UFS）
文件存储（UFS）是一种云存储服务，类似于我们电脑上的硬盘，但它是通过网络连接的共享存储空间。多个云主机可以同时访问同一个文件系统，实现数据共享和协作。

#### 2. 核心价值
- **数据共享**: 多个服务器可以同时读写同一个文件系统
- **高可用性**: 数据自动备份，避免单点故障
- **弹性扩展**: 存储容量可以根据需求动态调整
- **成本优化**: 按需付费，避免资源浪费

### 实例类型分类

#### 1. 存储类型
- **容量型**: 适合大容量存储需求，成本较低
  - 容量范围：500GB - 100TB
  - 适用场景：备份、归档、大数据存储
- **SSD性能型**: 适合高性能应用，IOPS更高
  - 容量范围：100GB - 20TB
  - 适用场景：数据库、实时应用、高并发访问

#### 2. 协议类型
- **NFS协议**: 网络文件系统协议
  - 支持Linux/Unix系统
  - 支持Windows（需安装NFS客户端）
  - 支持权限管理功能
  - 支持回收站功能
- **SMB协议**: 服务器消息块协议
  - 主要支持Windows系统
  - 不支持权限管理和回收站功能

#### 3. 部署模式
- **单点部署**: 单个文件系统实例
- **多挂载点**: 一个文件系统可以挂载到多个VPC网络
  - 最大支持5个挂载点
  - 每个挂载点对应一个VPC网络

#### 4. 地域覆盖
支持全球多个地域：
- 国内：华北一、华北二、上海二、广州、福建
- 海外：香港、台北、东京、洛杉矶、拉各斯、莫斯科、首尔、华盛顿、胡志明、伦敦

## 第二步：功能模块分类

### 1. 核心功能模块

#### 生命周期管理
- **创建文件系统**: 支持不同存储类型和协议类型
  - 文件系统名称：6-63位，包含字母数字和- _，且-不能作为第一个字符
  - 容量型：容量范围500GB-100TB
  - SSD性能型：容量范围100GB-20TB
  - 容量输入非100倍数时自动四舍五入调整
- **删除文件系统**: 支持资源清理和退费
  - 删除后对应退费订单生成
- **扩容文件系统**: 支持在线扩容（不支持缩容）
  - 容量跨度为100GB
  - 扩容时数据不丢失
  - 价格实时计算
- **地域覆盖**: 支持全球多个地域部署

#### 挂载管理
- **添加挂载点**: 支持最多5个VPC网络挂载
  - 每个挂载点对应一个VPC网络和子网
  - 挂载点名称要求：6-63位，包含字母数字和- _，且-不能作为第一个字符
  - 一个文件系统最多支持5个挂载点
- **删除挂载点**: 支持挂载点管理
- **主机挂载**: 支持Linux/Windows主机挂载
  - NFS协议：支持Linux/Unix系统，Windows需安装NFS客户端
  - SMB协议：主要支持Windows系统
- **文件传输**: 支持文件上传下载功能
  - 上传命令：`scp /本地目标文件地址 root@外网IP:/文件系统目录地址`
  - 下载命令：`scp root@外网IP:/文件系统目录地址 /本地目标地址`
  - 示例：`scp /Users/user/Desktop/file root@06.75.33.12:/mnt`

#### 权限管理（仅NFS协议）
- **创建权限规则**: 基于IP地址的访问控制
  - 来源地址：支持IP地址和网段格式
  - 读写权限：读写、只读两种模式
  - 规则生效延迟：1-2分钟
  - 默认选择"只读"权限
- **编辑权限规则**: 支持读写/只读权限切换
  - 规则变更后1-2分钟生效
  - 支持来源地址和读写权限修改
- **删除权限规则**: 支持规则管理
  - 支持单条规则删除
  - 一期不支持批量删除
- **复用到实例**: 支持权限规则复用
  - 可复用到其他文件系统实例
  - 复用后目标实例原规则自动失效

#### 回收站功能（仅NFS协议）
- **启用回收站**: 支持文件删除保护
  - 默认保留时间：3天
  - 可配置范围：1-180天
  - 仅支持NFS协议，SMB协议不支持
- **恢复文件**: 支持原路径和自定义路径恢复
  - 恢复文件：路径需以文件名结尾
  - 恢复文件夹：路径需以"/"结尾
  - 支持原路径和自定义路径两种方式
- **彻底删除**: 支持永久删除功能
  - 二次确认：确定永久删除以下文件？
  - 删除后无法恢复
- **清空回收站**: 支持批量清理
  - 二次确认：确定清空回收站下所有文件？
  - 清空后所有文件路径统一为"/"
- **任务管理**: 支持恢复/删除任务跟踪
  - 任务类型：恢复、删除
  - 任务状态：执行成功、恢复失败、删除失败、执行中
  - 支持任务筛选和分页

### 2. 运维功能模块

#### 基础运维
- **监控告警**: 支持性能监控和告警
- **操作日志**: 支持操作审计和追踪
- **业务组管理**: 支持资源分组管理
- **续费管理**: 支持资源续费

#### 数据管理
- **文件操作**: 支持文件创建、编辑、删除
  - 支持通过主机挂载后进行文件操作
  - 支持文件上传下载功能
- **目录操作**: 支持目录创建、删除
  - 支持通过主机挂载后进行目录操作
- **权限验证**: 支持读写权限验证
  - 只读权限：可读取文件，无法创建、编辑、删除
  - 读写权限：可进行所有文件操作
  - 权限切换后1-2分钟生效

## 第三步：自动化交付产物设计

### 自动化交付策略

#### 1. 基础功能回归 + 关联集合模板
- **限时要求**: 30分钟内完成
- **并行测试**: 支持多个工作流同时运行
- **智能回归**: 
  - 当前改动影响的功能：运行细分场景
  - 未影响的功能：正常回归测试

#### 2. 关联集合模板设计
- **基础回归验证**: 覆盖UFS基本功能
- **微服务覆盖**: 确保所有相关微服务正常启动
- **快速验证**: 发布时快速验证核心功能

#### 3. 回归测试工作流
设计六条核心工作流，根据发布可用区自动选择：
- 存储类型：容量型/SSD性能型
- 协议类型：NFS/SMB
- 部署模式：单挂载点/多挂载点
- 地域选择：根据测试需求选择

## 第四步：测试策略制定

### 测试分层设计

#### 1. 黑盒层测试
- **接口连续调用**: 模拟真实用户操作流程
- **文件操作场景**: 通过文件操作构造测试场景
- **异常场景设计**: 覆盖各种异常情况

#### 2. 灰盒层测试
- **微服务集成**: 验证服务间交互
- **数据一致性**: 确保数据在不同服务间的一致性
- **性能监控**: 监控关键性能指标

#### 3. 白盒层测试（较少）
- **代码分支覆盖**: 覆盖关键代码路径
- **权限控制逻辑**: 重点覆盖权限管理相关代码

#### 4. 平行层测试（例）
- **容灾自动化**: 
  - 挂载点故障测试
  - 网络连接中断测试
- **网络测试**: iperf打流测试
- **性能测试**: 
  - fio磁盘性能测试
  - 文件读写性能测试
  - 并发访问性能测试
- **主机连通性测试**: telnet连接测试

### 测试场景示例

#### 完整测试流程示例
```
CreateUFS → DescribeUFS → CreateMountPoint → MountToHost → 
FileOperations → PermissionTest → RecycleBinTest → 
ExpandUFS → DeleteMountPoint → DeleteUFS
```

#### 具体操作示例

**1. 创建文件系统**
```
- 选择存储类型：容量型/SSD性能型
- 选择协议类型：NFS/SMB
- 设置容量：500GB-100TB（容量型）或100GB-20TB（SSD性能型）
- 输入文件系统名称：6-63位字符
```

**2. 主机挂载（NFS协议）**
```
# CentOS/Rocky系统安装NFS客户端
sudo yum install nfs-utils

# Ubuntu/Debian系统安装NFS客户端
sudo apt-get install nfs-common

# NFSv3协议挂载
sudo mount -t nfs -o rsize=1048576,wsize=1048576,hard,timeo=600,retrans=2,noresvport,nfsvers=3,proto=tcp,mountproto=tcp,nolock,noacl 10.8.0.1:/ /mnt

# NFSv4协议挂载
sudo mount -t nfs -o rsize=1048576,wsize=1048576,hard,timeo=600,retrans=2,noresvport 10.8.0.1:/ /mnt2
```

**3. 主机挂载（SMB协议）**
```
# CentOS/Rocky系统安装CIFS客户端
sudo yum install cifs-utils

# Ubuntu/Debian系统安装CIFS客户端
sudo apt-get install cifs-utils

# SMB协议挂载
sudo mount -t cifs -o guest,uid=0,gid=0,rsize=1048576,wsize=1048576 //挂载地址/share /mnt
```

**4. 文件传输**
```
# 上传文件到文件系统
scp /Users/user/Desktop/file root@06.75.33.12:/mnt

# 从文件系统下载文件
scp root@106.75.33.12:/mnt/file /Users/user/Desktop/newfile
```

**5. 权限管理（NFS协议）**
```
# 创建权限规则
- 来源地址：192.168.1.0/24
- 读写权限：读写/只读
- 规则生效：1-2分钟延迟

# 权限验证
- 只读权限：无法创建文件 mkdir: 无法创建目录 "eee": Permission denied
- 读写权限：可以正常创建文件
```

## 第五步：具体测试用例设计

### 1. 主流程测试用例

#### 创建文件系统测试
- **测试目标**: 验证文件系统创建功能
- **测试场景**: 
  - 不同存储类型（容量型/SSD性能型）
  - 不同协议类型（NFS/SMB）
  - 不同容量范围
  - 不同地域部署
- **验证点**: 
  - 创建成功，订单生成
  - 资源信息正确
  - 日志记录完整

#### 挂载管理测试
- **测试目标**: 验证挂载点管理功能
- **测试场景**: 
  - 添加挂载点（最多5个）
    - 挂载点名称：6-63位，包含字母数字和- _，且-不能作为第一个字符
    - VPC选择：选择目标VPC网络
    - 子网选择：选择VPC下的子网
    - 超过5个挂载点时接口报错：quota over run
  - 删除挂载点
  - 主机挂载验证
    - NFS协议：需要安装nfs-utils或nfs-common
    - SMB协议：需要安装cifs-utils
- **验证点**: 
  - 挂载点创建成功
  - 主机可以正常挂载
  - 文件操作正常
  - 挂载命令执行成功：`df -h`显示挂载信息

#### 权限管理测试（NFS协议）
- **测试目标**: 验证权限控制功能
- **测试场景**: 
  - 创建读写权限规则
    - 来源地址：支持IP地址和网段格式
    - 重复IP地址：报错"输入IP地址及网段已存在"
    - 特殊字符：报错"请输入正确的ip地址及网段"
  - 创建只读权限规则
    - 默认选择"只读"权限
  - 权限切换验证
    - 只读权限：无法创建文件，报错"Permission denied"
    - 读写权限：可以正常创建文件
    - 权限切换延迟：1-2分钟生效
- **验证点**: 
  - 权限规则生效
  - 读写权限正确
  - 权限切换及时
  - 权限复用功能正常

#### 回收站功能测试（NFS协议）
- **测试目标**: 验证文件保护功能
- **测试场景**: 
  - 启用回收站
    - 默认保留时间：3天
    - 可配置范围：1-180天
    - 输入范围外数值：自动调整为边界值
    - 输入小数点：自动过滤，不支持小数
  - 文件删除和恢复
    - 恢复文件：路径需以文件名结尾
    - 恢复文件夹：路径需以"/"结尾
    - 路径格式错误：报错"请输入正确路径"
  - 任务管理
    - 任务类型：恢复、删除
    - 任务状态：执行成功、恢复失败、删除失败、执行中
    - 恢复失败：显示问号提示"当前文件/文件夹内容恢复失败，请联系技术支持"
- **验证点**: 
  - 删除文件进入回收站
  - 恢复功能正常
  - 任务状态正确
  - 清空回收站功能正常
  - 关闭并清空功能正常

### 2. 专项功能测试用例

#### 文件操作测试
- **测试目标**: 验证文件系统基本功能
- **测试场景**: 
  - 文件创建、编辑、删除
    - 通过主机挂载后进行文件操作
    - 验证文件内容一致性
  - 目录创建、删除
    - 通过主机挂载后进行目录操作
    - 验证目录结构正确性
  - 文件上传下载
    - 上传命令：`scp /本地目标文件地址 root@外网IP:/文件系统目录地址`
    - 下载命令：`scp root@外网IP:/文件系统目录地址 /本地目标地址`
    - 示例：`scp /Users/user/Desktop/file root@06.75.33.12:/mnt`
- **验证点**: 
  - 文件操作成功
  - 数据一致性
  - 性能符合预期
  - 上传下载功能正常

#### 扩容功能测试
- **测试目标**: 验证存储扩容功能
- **测试场景**: 
  - 在线扩容
    - 容量跨度为100GB
    - 不支持缩容
    - 扩容时数据不丢失
  - 容量边界测试
    - 输入非100倍数：四舍五入自动调整
    - 容量型：500GB-100TB
    - SSD性能型：100GB-20TB
  - 价格计算验证
    - 扩容时价格实时计算
    - 与公有云价格比对正确
- **验证点**: 
  - 扩容成功
  - 数据不丢失
  - 价格计算正确
  - 订单生成正确

#### 地域覆盖测试
- **测试目标**: 验证多地域部署
- **测试场景**: 
  - 所有支持地域
    - 国内：华北一、华北二、上海二、广州、福建
    - 海外：香港、台北、东京、洛杉矶、拉各斯、莫斯科、首尔、华盛顿、胡志明、伦敦
  - 跨地域访问
    - 每个地域都受权限位控制
    - 当前环境已在IPv6网络下
- **验证点**: 
  - 各地域创建成功
  - 网络连通性正常
  - 权限控制正确

## 总结

文件存储自动化测试设计采用分层测试策略，通过业务本质理解、功能点梳理、自动化交付产物设计、测试策略制定和实施计划，构建了一个完整的自动化测试体系。该体系能够有效保障文件存储产品的质量，提高测试效率，支持快速迭代和发布。

### 关键成功因素

1. **业务理解**: 深入理解文件存储的业务本质和使用场景
2. **场景覆盖**: 全面覆盖各种存储类型、协议类型和部署模式
3. **自动化程度**: 高自动化程度，减少人工干预
4. **持续优化**: 根据业务发展持续优化测试策略和用例

### 预期收益

1. **质量保障**: 通过自动化测试提高产品质量
2. **效率提升**: 减少手工测试时间，提高测试效率
3. **成本降低**: 降低测试人力成本
4. **快速交付**: 支持快速迭代和发布
