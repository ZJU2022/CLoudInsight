# Linux内核测试方案总结

## 1. 测试目标

### 1.1 核心目标
- **稳定性验证**：确保内核在长期运行下的可靠性，避免死锁、内存泄漏、系统崩溃等问题
- **性能评估**：评估内核在各种负载情况下的处理速度、资源消耗和响应时间等关键指标
- **模块覆盖**：测试用例应尽可能覆盖多个内核模块，包括：
  - 虚拟化模块
  - 网络吞吐
  - 磁盘I/O
  - VM迁移

### 1.2 测试环境要求
- 尽可能模拟真实使用场景
- 在VM中进行各种workload测试
- 在host上进行性能压测

## 2. 测试策略

### 2.1 特性验证
- 针对新引入功能编写专项测试用例
- 确保行为符合设计文档和用户需求

### 2.2 自动化测试
- 使用持续集成系统进行自动化回归测试
- 快速发现和定位问题

## 3. 测试工具集

### 3.1 系统性能测试工具

#### sysbench
- **用途**：CPU性能基准测试
- **版本**：1.0.20
- **测试命令**：`sysbench cpu run --cpu-max-prime=20000 --threads=8 --time=60`
- **关键指标**：
  - CPU速度：3782.31 events/second
  - 延迟：平均2.11ms，95th percentile 2.14ms

#### UnixBench
- **用途**：综合系统性能基准测试
- **版本**：6.6.0
- **测试项目**：Dhrystone 2、PI圆周率计算等
- **特点**：提供详细的性能评分和对比数据
- **测试命令**： ./Run -v ； time echo "scale=5000; 4*a(1)" | bc -l -q

### 3.2 网络性能测试工具

#### nginx + ApacheBench
- **用途**：Web服务器性能测试
- **版本**：nginx/1.20.1, ab/2.3
- **测试命令**：`ab -n 10000 -c 100 -s 1 http://localhost/index.html`
- **关键指标**：
  - 请求处理：2136.97 requests/second
  - 平均响应时间：46.795ms

#### iperf3
- **用途**：网络带宽和延迟测试
- **版本**：3.9
- **测试模式**：UDP带宽测试
- **关键指标**：300 Mbits/sec带宽，0.026ms抖动
- **测试命令**：server: iperf3 -s -i 2 -p 5201 -V + client: iperf3 -c <ip> -p 5201 -b 300M -u -t 120

### 3.3 存储性能测试工具

#### fio
- **用途**：磁盘I/O性能测试
- **版本**：3.35
- **测试场景**：随机读测试
- **关键指标**：
  - IOPS：26.8k
  - 带宽：105MiB/s
  - 延迟：平均19ms
- **测试命令**：fio --name=job1 -direct=1 -iodepth=32 -rw=randread  -ioengine=libaio -bs=4k -size=20G -numjobs=16 -runtime=1000 -group_reporting -filename=/data/test

### 3.4 数据库性能测试工具

#### Redis Benchmark
- **用途**：Redis数据库性能测试
- **版本**：6.2.18
- **关键指标**：
  - 吞吐量：8244.02 requests/second
  - 延迟：平均0.698ms，P99 5.055ms
  -  redis-benchmark -h <ip> -p <port> -c 50 -n 10000

## 4. 测试执行建议

### 4.1 测试顺序
1. **基础性能测试**：sysbench、UnixBench
2. **存储性能测试**：fio
3. **网络性能测试**：iperf3、nginx+ab
4. **应用层测试**：Redis、MySQL等数据库
5. **高级特性测试**：ib_write_bw、NCCL

### 4.2 测试环境准备
- 确保测试环境干净，无其他负载干扰
- 记录测试前的系统状态（CPU、内存、磁盘使用率）
- 准备足够的测试数据

### 4.3 结果分析
- 建立性能基线数据
- 对比不同内核版本的性能差异
- 关注异常值和性能回归
- 生成详细的测试报告

## 5. 自动化方案

测试内核的本质是在只有内核这一个变量的情况，内核变了对于机器的性能有没有什么影响（替换内核替换的是物理机的内核，测试需要虚拟机 + 物理机）
第一步：创建公有云虚拟机，在虚拟机上采集基准数值
第二步：在管理网申请物理机；然后采集物理机的基准数值（基准数值是机器上运行sysbench，unixbench，fio，iperf3等工具采集的数值）
第三步：编写自动化，将圆周率计算，fio，sysbench等工具集成至自动化，并且根据基准值设置断言（断言设置为基准值上下浮动5%，如果超过此范围证明本次内核变更有问题）
第四步：交付自动化，根据效率评估串行和并行两种模式
第五步：根据需求不断迭代，虚拟化：缺KVM/QEMU热迁移、vCPU调度测试；网络：缺TCP堆栈、iptables/nftables压力测试；存储：缺ext4/XFS/Btrfs文件系统对比测试；内核泄漏；故障注入；vm迁移，宿主机资源竞争等等
